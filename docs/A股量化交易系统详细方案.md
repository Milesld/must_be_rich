# A股量化交易系统详细方案

> **方案性质**：本文是一份系统级的工程实施方案，融合了方法论设计、技术选型、合规要求与实施路线图。
> **核心认知**：没有任何系统能稳定准确地预测股价；目标是**提高胜率、控制风险、形成正期望**。
> **风险声明**：本文不构成任何投资建议。量化交易存在本金损失风险，实盘前必须经过充分回测与模拟验证。

---

## 一、系统总览

### 1.1 系统目标

构建一套 **"长期选股 + 盘前推荐 + 实时日内预测"三子系统解耦**的A股量化交易平台，覆盖数据采集、特征工程、模型训练、回测验证、实时推理、风控、仓位管理和退出执行的全流程闭环。三子系统在时间维度上形成互补：长期选股提供底池和方向约束，盘前推荐每日精选当日值得关注的标的和入场区间，日内预测进行盘中买卖择时。

### 1.2 整体架构

```
┌──────────────────────────────────────────────────────────────────────┐
│                        组合/决策层                                    │
│           资金分配 | 总风控 | 回撤熔断 | 合规检查                      │
├──────────────────────────────────────────────────────────────────────┤
│  长期选股子系统      盘前推荐子系统         实时/日内预测子系统        │
│  · 月度调仓          · 每日盘前(8:00-9:15)  · 分钟~小时预测            │
│  · 多因子横截面打分  · 隔夜信号+竞价分析     · 分位数回归/分类          │
│  · 基本面+估值驱动   · 今日关注清单+入场区间  · 资金+情绪+盘口驱动      │
│         │                  │                      │                  │
│         └──────────┬───────┘                      │                  │
│                    │ 底池约束、方向先验               │                  │
│                    ▼                              ▼                  │
├──────────────────────────────────────────────────────────────────────┤
│                     共享数据/特征平台                                  │
│            DolphinDB (主力) + ClickHouse (辅助)                       │
│                   + Redis/Dragonfly (特征缓存)                        │
│                        ↑ Redpanda 消息总线                            │
├──────────────────────────────────────────────────────────────────────┤
│  数据采集层                                                           │
│  行情(日K/分钟/tick/L2) | 基本面 | 资金流 | 舆情 | 宏观                │
│  盘前专属：隔夜海外市场 | 盘前公告 | 集合竞价 | 商品/汇率              │
└──────────────────────────────────────────────────────────────────────┘
```

### 1.3 核心设计原则

1. **模型层彻底解耦，数据层共享，资金层硬隔离，组合层有限协同**
2. **三子系统分层接力**：长期选股定底池方向 → 盘前推荐日频精选 → 日内预测分钟择时；各层独立建模、独立评估，通过共享特征平台和信号总线衔接
3. **过拟合是头号杀手**，一切回测必须计入T+1、涨跌停、停牌、交易成本、滑点
4. **风险最小化的发力点80%在组合结构与相关性**
5. **一切权重和退出规则都要能扛住A股的T+1与涨跌停才算数**
6. **先把"卖不出去"当成必然会发生的场景来设计**

## 二、A股交易规则与合规要求

### 2.1 涨跌停限制

| 板块 | 现行规则 | 2026年7月6日起 |
|------|----------|---------------|
| 主板普通股 | ±10% | 不变 |
| 主板ST/*ST股 | ±5% | 改为 ±10% |
| 创业板 (300/301) | ±20% | 不变 |
| 科创板 (688) | ±20% | 不变 |
| 北交所 (8/83/87/88/920) | ±30% | 不变 |

**系统要求**：涨跌停限制设计为**板块级配置参数**，支持历史回测时按时间段切换ST股涨跌幅（2026年7月6日前5%、之后10%）。

不设涨跌幅的情形（新股前5日、重大重组复牌等）需单独处理，但仍受盘中临时停牌约束（较开盘价涨跌30%/60%触发10分钟停牌）。

### 2.2 T+1制度

- 股票T+1：T日买入，T+1日方可卖出
- 资金T+0可用：卖出所得资金当日可继续买入，但不可转出银行
- 资金T+1可取：T+1日结算后方可提现
- 例外：可转债T+0、B股T+3
- 转融券自2024年3月18日起T+1

**系统影响**：
- 日内系统三种使用场景：①已有持仓的卖出择时、②今日买入时机选择（仅影响建仓成本）、③变相T+0（利用底仓做日内回转，唯一能当日变现的场景）
- 卖出资金当日可用但不可取，仓位计算需考虑此约束

### 2.3 交易时间

| 时段 | 时间 | 可撤单 |
|------|------|--------|
| 开盘集合竞价 | 9:15–9:25 | 9:15–9:20可撤，9:20–9:25不可撤 |
| 连续竞价（上午） | 9:30–11:30 | 可 |
| 午间休市 | 11:30–13:00 | — |
| 连续竞价（下午） | 13:00–14:57 | 可 |
| 收盘集合竞价 | 14:57–15:00 | 不可 |

**2026年7月6日起新增**：盘后固定价格交易（15:05–15:30）扩展至全部A股和ETF，以当日收盘价成交、时间优先撮合。系统可利用此机制处理盘中未完成的调仓。

### 2.4 交易成本

| 费用项 | 费率 | 说明 |
|--------|------|------|
| 印花税 | 0.05%（万分之五） | **仅卖出时单边征收**，2023年8月28日起减半 |
| 佣金 | 万1.0~万1.5（可协商） | **最低5元/笔**，买卖双向，最低5元规则不可减免 |
| 过户费 | 0.01‰（十万分之一） | 买卖双向 |
| 经手费 | 约0.0341‰ | 含在佣金中（全佣） |
| 证管费 | 约0.02‰ | 含在佣金中（全佣） |

**系统要求**：
- 回测必须精确建模印花税（仅卖方单向）、佣金最低5元规则、过户费
- 小资金的整手化公式中，单笔佣金占比应<0.1%，即单笔金额≥5000~10000元较舒适
- ETF交易免征印花税，需与股票区分

### 2.5 最小交易单位

| 板块 | 最小申报 | 递增方式 |
|------|---------|----------|
| 主板 | 100股（1手） | 100股整数倍 |
| 科创板 | 200股起 | 超200股后1股递增（如201、250） |
| 创业板 | 100股 | 100股整数倍 |
| 北交所 | 100股 | 100股整数倍 |

**科创板注意事项**：
- 限价申报200股起，市价申报上限5万股，限价申报上限10万股
- "价格笼子"：连续竞价买入申报价≤买入基准价的102%，卖出≥卖出基准价的98%，超出废单
- 余额不足200股须一次性卖出

### 2.6 程序化交易合规（2025年7月7日起施行）

**这是"能否合规上线"的前置条件，必须优先处理。**

#### 报告义务

首次程序化交易前须向券商报告，内容包括：
- 账户基本信息、资金信息
- **交易策略类型及主要内容**
- **最高申报速率**、单日最高申报笔数
- 交易软件信息（名称、版本号、开发主体）
- 信息变更须履行变更报告义务
- 穿透报告：开展收益互换等须穿透报告客户信息

#### 高频交易认定标准

- 单账户每秒申报/撤单笔数 ≥300笔，或
- 单账户全日申报/撤单笔数 ≥20,000笔

**系统须将每秒≤300笔、全日≤20,000笔作为硬限制**，超出触发告警和自动降频。

#### 高频交易额外义务

- 额外报告：服务器所在地、系统测试报告、故障应急方案
- 差异化收费：根据申报撤单笔数/频率加收流量费、撤单费、行情信息使用费（具体费率由交易所另行制定）
- 重点监控：更严格的异常交易监控

#### 四类重点监控的异常交易行为

1. 瞬时申报速率异常
2. 频繁瞬时撤单（如1秒内撤单率>70%）
3. 频繁拉抬打压
4. 短时间大额成交

**系统要求**：
- 撤单率监控：1秒内撤单率超过70%则告警并暂停
- 风控模块需内置报告信息管理功能
- 预留高频交易差异化收费的成本模型接口

#### 牌照与资质

目前为**报告制**（无独立量化牌照），但政策趋严：
- 个人投资者：通过券商向交易所报告，一般要求50万以上资金，风险测评C4+
- 私募量化：须完成AMAC私募管理人登记
- 高频交易专项牌照制度正在酝酿中（2025年两会提案）

### 2.7 做空与对冲工具

#### 融资融券

- 开通条件：前20日日均资产≥50万、交易经验≥6个月、风险测评C4/C5、知识测试80分
- **融券实际障碍**：截至2025年8月A股融券余额仅约139亿（两融总余额约2万亿），券源极有限，多为大盘蓝筹
- 融券利率：年化5%-6%
- **禁止利用融券做日内回转**

#### 股指期货（主要对冲工具）

| 品种 | 代码 | 合约乘数 | 最小变动 | 每手保证金（约） |
|------|------|----------|----------|-----------------|
| 沪深300 | IF | 300元/点 | 0.2点 | ~12万元 |
| 上证50 | IH | 300元/点 | 0.2点 | ~10万元 |
| 中证500 | IC | 200元/点 | 0.2点 | ~13万元 |
| 中证1000 | IM | 200元/点 | 0.2点 | ~14万元 |

- 交易所最低保证金12%，期货公司实收14%-15%
- 手续费：开仓/隔日平仓 0.23%%；日内平今仓 2.3%%（开仓的10倍，抑制日内投机）
- 开通条件：连续5日可用资金≥50万、知识测试80分、10笔实盘或20笔仿真交易

#### ETF期权 / 股指期权

| 市场 | 品种 |
|------|------|
| 上交所 | 上证50ETF(510050)、沪深300ETF(510300)、中证500ETF(510500)、科创50ETF(2只) |
| 深交所 | 沪深300ETF(159919)、中证500ETF(159922)、创业板ETF(159915)、深证100ETF(159901) |
| 中金所 | 沪深300股指期权、中证1000股指期权、上证50股指期权 |

- ETF期权合约单位10,000份，实物交割；股指期权合约乘数100元/点，现金交割
- 开通条件与股指期货一致

**系统策略建议**：
- 新手优先用"降仓位 + 留现金"替代复杂对冲
- 进阶使用股指期货对冲系统性beta
- 注意对冲成本：基差、贴水、权利金、保证金占用
- beta敞口存在不完全匹配的基差风险

### 2.8 熔断机制

A股**目前无大盘指数熔断**（2016年1月试行4天后叫停）。当前风险控制主要依赖个股涨跌停制度以及新股盘中临时停牌机制（较开盘价涨跌超30%或60%时，临时停牌10分钟）。

### 2.9 北向资金数据现状

- 2024年5月13日起：取消盘中实时交易数据
- 2024年8月19日起：取消每日净流入/流出数据，改为**按季度披露**

**仍保留**：每日成交总额及总成交笔数、前十大成交活跃股、季度末单只持股数量、年度汇总

**已取消**：盘中实时买卖数据、每日净买入/卖出、单只个股每日持仓变化、历史累积净买入长周期曲线（仅保留近4年）

**系统影响**：北向资金已降级为**低频因子**（仅季度持仓变化可用，每季第5个交易日公布上季末数据）。日内系统需改用龙虎榜、主力大单等替代信号。

## 三、数据层设计

### 3.1 数据分类与来源选型

#### 3.1.1 行情数据

| 数据类型 | 免费方案 | 商业方案 | 机构方案 |
|----------|---------|---------|---------|
| 日K线 | AkShare / Baostock | Tushare Pro (500元/年) | Wind (3.98万+/年) / iFinD (1.45万+/年) |
| 分钟K线 | AkShare | Tushare 分钟线 (2000元/年) | Wind / iFinD |
| Level-2逐笔 | — | 券商QMT（~200元/月，50万资金门槛）/ PTrade（国金证券，10万门槛免费） | 交易所直连（50万+/年）/ 银禾金融 |
| Tick级 | — | QMT/miniQMT | 银禾金融（历史2000年起，20TB+） |

**A股数据源关键提醒**：
- **复权方式必须在全系统统一**（前复权/后复权/不复权），不同数据源口径不一致是回测最常见bug
- **退市/ST数据完整性**：Tushare/AkShare免费数据退市股常缺失，导致幸存者偏差；Wind/iFinD在退市数据上最完整
- **财报实际披露日 vs 报告期截止日**：用错会产生 look-ahead bias，回测须用实际披露日

### 3.2 数据存储架构

```
行情源 (UDP/TCP/API)
      │
      ▼
  Redpanda 消息总线 (兼容Kafka协议，C++原生，微秒级尾延迟)
      │
      ├──▶ DolphinDB (主力时序数据库)
      │      · 日线/分钟/tick/L2 行情存储与查询
      │      · 流批一体因子计算引擎 (延迟≤5ms)
      │      · 内置2000+金融专用函数
      │      · 存储压缩比约1:10
      │
      ├──▶ ClickHouse (辅助OLAP分析)
      │      · 全市场回测聚合查询
      │      · 合规报告生成
      │      · 冷数据查询
      │
      ├──▶ Redis / Dragonfly (热数据缓存)
      │      · 实时特征在线服务 (亚毫秒读取)
      │      · 当日行情缓存
      │      · 信号/因子最新值存储
      │
      └──▶ MySQL / TimescaleDB (业务数据)
             · 订单记录、成交记录
             · 持仓、账户、资金流水
             · 合规报告记录
             · ACID保证
```

#### 商业 vs 开源方案

| 组件 | 商业方案（推荐） | 开源方案（备选） |
|------|----------------|----------------|
| 时序数据库 | **DolphinDB**（中国量化事实标准，130+付费客户含幻方/九坤/30家券商） | ClickHouse + TimescaleDB |
| 消息总线 | **Redpanda** Enterprise | Redpanda (OSS) 或 AutoMQ |
| 缓存 | **Dragonfly**（Redis兼容，多线程，更高吞吐） | Redis Cluster |
| 业务存储 | MySQL / PostgreSQL | — |

**DolphinDB成本参考**：商业授权，根据节点数和功能模块报价，需向智臾科技询价（通常数万至数十万/年，视规模而定）。个人/小团队探索期可先用ClickHouse（开源免费）起步。

### 3.3 数据清洗与质量保障

1. **复权处理**：统一采用前复权，确保全系统一致；数据源变更时做交叉验证
2. **停复牌标记**：与交易所公告核对，使用status字段标记交易状态
3. **退市股票保留**：回测数据库须保留已退市/ST股票全量历史数据，防止幸存者偏差
4. **财报时间戳**：严格区分"报告期截止日"与"实际披露日"，特征工程只使用后者之前可知的信息
5. **数据完整性自动化检查**：
   - 每日行情到达率（应有N只股票，实收M只，缺失告警）
   - 价格合理性（涨跌幅超限、OHLC逻辑矛盾告警）
   - 财务数据一致性（勾稽关系校验）

## 四、特征工程

> **特征工程决定模型上限**，数据质量决定特征工程的基础。

### 4.1 因子分类体系

#### 4.1.1 技术面因子

- 动量类：N日收益率、加权动量、alpha动量（剔除beta/行业）
- 波动率类：已实现波动率、振幅、ATR
- 成交量/流动性：换手率、成交量比（VWAP/均值）、Amihud非流动性指标
- 技术指标：RSI、MACD、布林带位置、均线多空排列
- 盘口（需L2）：订单不平衡、买卖价差、深度加权价格
- 日内特有：相对VWAP位置、距开盘/昨收的百分比、"距收盘剩余时间"

#### 4.1.2 基本面因子

- 估值：PE/PB/PS/PCF、PEG、股息率、EP（1/PE）
- 盈利质量：ROE/ROA/ROIC、毛利率/净利率趋势、经营现金流/净利润
- 成长性：营收/净利同比/环比增速、预期增速（一致预期，注意时间戳）
- 财务健康：负债率、流动/速动比率、利息保障倍数、自由现金流
- 治理：股权集中度、机构持股变化（季度频率）、股权激励

#### 4.1.3 资金面因子

- 主力资金流向（大单净流入/流出）
- 龙虎榜买卖席位统计
- 融资融券余额变化（融券数据极有限）
- 北向资金季度持股变化（仅季度频率可用！）
- 限售解禁时间表（解禁比例、解禁市值）

#### 4.1.4 情绪/事件因子

- 涨停家数、连板高度、炸板率（市场情绪温度计）
- 新闻/公告NLP情绪评分
- 分析师研报情绪、评级调整
- 社交媒体热度（雪球/股吧讨论量）
- 业绩预告类型和预期差

#### 4.1.5 板块/行业因子

- 行业分类（申万/中信/GICS，选一套统一使用）
- 行业动量、行业轮动信号
- 板块内排名（个股在行业内的因子分位数）

### 4.2 特征工程规范性要求

1. **严防Look-ahead Bias（前视偏差）**
   - 财务数据必须使用"实际披露日"而非"报告期截止日"作为可用时间点
   - 构建 time-travel safe 特征管线：每个时间点只能用该点之前已知的信息

2. **幸存者偏差处理**
   - 回测数据库包含已退市/ST股票
   - 不在回测时假设"今天的成分股就是历史上的成分股"来做筛选（即不能剔除已退市股票）

3. **缺失值处理**
   - 区分"数据确实没有"（如早期股票无L2数据）和"该指标无意义"（如负利润无法算PE）
   - 做缺失率监控（单因子的缺失占比过高则暂停使用）

4. **异常值处理**
   - MAD（中位数绝对偏差）去极值：±5MAD缩尾
   - 行业市值中性化：先对行业和市值做正交，再取残差作为纯因子暴露

### 4.3 特征存储

**推荐架构**（中等规模团队）：
```
离线计算链：DolphinDB 因子计算 → 离线存储 → Airflow/Dagster 调度
在线服务链：行情Tick → DolphinDB 流计算(≤5ms) → 实时特征更新 → Redis/Dragonfly(亚毫秒读取)
```

**关键要求**：离线回测和实时推理使用**完全相同的特征计算代码**（DolphinDB流批一体架构天然满足）。

## 五、模型层设计

### 5.1 建模策略总纲

**核心建议**：建模为**分类**或**排序**，而非直接回归价格——后者对噪声更敏感。

#### 长期选股模型

| 推荐模型 | 任务定义 | 说明 |
|---------|---------|------|
| LightGBM 排序模型 | LambdaRank / 横截面打分 | 主力，表格数据最优 |
| LightGBM 分类 | 未来N日跑赢基准的概率 | 可解释性强 |
| CatBoost | 含大量类别特征时 | 行业/板块/ST状态等 |
| 多因子线性 | 基线模型 | 先跑通再上非线性 |

#### 日内预测模型

| 推荐模型 | 任务定义 | 说明 |
|---------|---------|------|
| LightGBM 分类 | 涨/跌/平三分类 | 建模为概率输出 |
| 分位数回归 (LightGBM/LSTM) | 预测收盘价分布 | 获得预测区间而非点值 |
| XGBoostLSS / NGBoost | 概率预测 | 全分布建模，不确定性估计 |

#### NLP舆情模型

| 推荐模型 | 适用场景 | 推理延迟 |
|---------|---------|---------|
| FinSenti-Qwen3-0.6B (INT8) | 实时新闻情绪 | <50ms (CPU) |
| Qwen3-8B rLoRA | 日频情绪因子批量生成 | GPU批量推理 |
| DeepSeek-R1-Distill-Qwen-7B | 复杂研报解读 | 离线批处理 |

### 5.2 模型训练与评估

#### 训练注意事项

- **标签时间归一化**（日内）：将"距收盘剩余时间"作为输入特征或按时段分桶分别建模
- **条件化于时间**：模型需知道"现在几点"——预测窗口随时间动态收缩
- **拆出Beta**：收益率拆为 市场Beta + 行业 + 个股Alpha，避免模型偷预测大盘
- **样本加权**：近期样本给更高权重（指数衰减），但不要极端
- **Purged Cross-Validation**：金融时序不能用随机K-Fold，须用时序划分且相邻训练/验证间设gap

#### 评估指标

| 场景 | 关键指标 | 辅助指标 |
|------|---------|---------|
| 分类模型 | AUC、准确率 | 校准度（Reliability Diagram）、各类别Precision/Recall |
| 排序模型 | Rank IC / ICIR | 分层单调性（按分位数分组收益是否单调） |
| 回归/分布 | Pinball Loss / CRPS | 校准度、Sharpe Ratio（基于预测） |
| 日内特有 | 方向准确率（是否>55%？）、日内夏普 | 按剩余时间分桶评估 |

**现实预期**：短期方向准确率能稳定超过55%已经很难得。赚钱靠**正期望 + 严格风控 + 低成本**，而非单次预测准。

### 5.3 模型风险管理

1. **模型衰减监控**：持续跟踪Rank IC滚动均值，IC低于阈值→触发重训练
2. **因子拥挤度监控**：监测组合与市场主流持仓的相关性
3. **过拟合检验**：样本外表现 vs 样本内表现的差距，差距过大→模型退化
4. **在线-离线一致性检查**：实时特征与回测特征的值域分布须一致

## 六、盘前推荐子系统

> 盘前推荐是"长期选股 → 日内预测"之间的日频桥梁：利用隔夜增量信息，从长期底池中精选当日值得关注的标的，为日内系统提供聚焦范围。

### 6.1 定位与设计动机

#### 为什么需要盘前推荐子系统？

现有长期选股系统按月度频率给出排序，覆盖全市场；日内预测系统按分钟频率处理实时信号。两者之间存在一个空白：

- **时间空白**：长期系统的月度排序无法反映"昨晚发生了什么"
- **信息空白**：大量关键信息在收盘后才释放——美股走势、期货夜盘、上市公司公告、龙虎榜复盘、政策发布——这些隔夜增量在次日开盘前必须被消化
- **聚焦空白**：日内系统如果面对全市场4000+只股票实时打分，延迟和成本都不可接受；需要一个日频筛选将关注范围缩到可管理的几十只

盘前推荐填补了这个空白——它是日频的、信息驱动的、范围聚焦的。

#### 在整体架构中的位置

```
前一日 15:00 收盘
      │
      ├── 日终清算、数据入库
      ├── 龙虎榜复盘、涨停原因分析
      ├── 模型训练/重训练（日频定时任务）
      │
次日 凌晨-7:00
      │
      ├── 采集隔夜海外市场（美股、A50期货、中概股）
      ├── 采集盘前公告/新闻
      ├── 采集商品/汇率
      │
次日 8:00-8:45
      │
      ├── ★ 盘前推荐系统运行 ★
      ├── NLP处理隔夜公告 → 事件分类
      ├── 隔夜映射计算 → 个股开盘方向预估
      ├── 融合长期底池评分 + 隔夜信号 → 今日推荐排序
      ├── 生成推荐清单 + 建议入场区间
      │
次日 8:45-9:15
      │
      ├── 输出给日内系统作为"今日关注池"
      ├── 输出给用户（推荐报告/推送）
      │
次日 9:15-9:25
      │
      ├── 集合竞价分析引擎运行
      ├── 实时修正推荐（超预期/不及预期的竞价信号）
      │
次日 9:30 开盘
      │
      └──→ 日内预测系统接管，基于推荐清单做实时择时
```

```
        │

                                      │

                                      ├── 竞价强度确认 ──→ 调整个股置信度
                                      │
                                      ▼ (9:25)
                              最终推荐清单 → 日内系统今日关注池
```

### 6.3 盘前推荐的信号融合策略

与日内的关系：长期评分作为盘前模型的**基线特征**输入（而非硬约束），盘前模型可以在充分的隔夜信号支持下给出高于长期评分的排序——这对应着"事件催化剂带来的短期机会"。

### 6.5 盘前推荐的独特风险

#### 6.5.1 集合竞价虚假信号

9:15-9:20 申报可撤销，是虚假大单的高发期：
- 大户可能挂大买单制造抢筹假象，9:19:59撤销，在9:20-9:25期间真实卖出
- 系统必须在9:20分界点前后分别建模，9:15-9:20的申报量仅作参考，不作为核心信号
- 在9:20前不产生最终推荐信号，仅标记"可疑"和"需后续确认"

#### 6.5.2 隔夜映射的不稳定性

- 中概股与A股对应标的不是1:1映射（同一家公司可能对多只A股，或无对应A股），需维护映射表
- 海外市场的夜盘波动在A股开盘后可能迅速被定价完毕——盘前推荐的有效窗口极短
- A50期货流动性不如日盘，极端行情下期货价格可能失真
- 美股交易时间（夏令时）至北京时间凌晨4:00，6:00采集时距收盘仅2小时——凌晨可能有新的信息释放（如盘后财报），系统需在8:00前再次拉取确认

#### 6.5.3 信息时效性竞争

- 盘前推荐在8:45生成后，到9:30开盘还有45分钟——期间可能有新的公告或新闻
- 系统需在8:45-9:15之间持续监听公告流，如有重大信息，增量更新推荐（不重新全量计算）
- 集合竞价数据在9:25后才有最终结果——最终推荐清单在9:25做一次修正
- **系统可用性要求高**：每天8:00-9:30是盘前推荐的黄金窗口，必须在规定时间内完成全部计算

#### 6.5.4 与日内系统的衔接风险

- 盘前推荐的排序不代表日内应该买入——它只是"值得关注"，具体交易时机由日内系统决定
- 盘前推荐的置信度不能过高：隔夜信号在开盘后可能迅速被市场消化，出现"开盘即兑现"的情况
- 集合竞价信号修正后，有些盘前推荐可能需要降级甚至移除——日内系统需能处理"推荐被撤回"

### 6.6 回测适配

盘前推荐的时域比较特殊——目标不是收盘价，而是**开盘跳空方向和开盘后N分钟的走势**。回测需适配以下特殊性：

- **标签定义**：开盘价 vs 昨收价的涨跌幅（跳空预测）、开盘后30分钟的涨跌幅（开盘后方向预测）
- **数据时间戳严格要求**：回测每个交易日的盘前时刻，只能使用该时刻之前已知的隔夜数据——不能使用当日开盘后的数据
- **竞价数据回放**：需要历史集合竞价数据（虚拟开盘价序列），Tushare/AkShare的分钟线通常不包含竞价——可能需要Level-2历史数据源（银禾金融等）
- **评估周期短**：推荐有效期仅1天（开盘即过期），滚动评估需更频繁的Walk-Forward
- **样本量小**：每日仅一次推荐事件，需要多年数据才能获得足够的评估样本量

评估指标：

| 指标 | 定义 | 基准 |
|------|------|------|
| 开盘方向准确率 | 预测方向与实际开盘涨跌方向一致的比例 | >55%及格 |
| 推荐清单日内最大涨幅均值 | 推荐清单内个股当日最大涨幅的均值 vs 全市场均值 | 显著优于随机选股 |
| 高开选中率 | 预测高开的股票中实际高开的比例 | — |
| 融合排序 IC | 盘前融合排序分数 vs 当日日内收益的Rank IC | >0.03及格 |
| 推荐命中率 | 日内系统从推荐清单中找到交易机会的比例 | — |

| **hftbacktest** | 逐笔仿真 | ★★（需自建格式） | 极快 | 高频策略（Rust内核） |

### 7.2 回测引擎必备功能

1. **交易成本精确建模**：
   - 印花税（卖0.05%，ETF免，需区分品种）
   - 佣金（最低5元规则，买卖双向）
   - 过户费（买卖双向0.01‰）
   - 滑点（按流动性分层建模：大盘0.1%、小盘0.3%-0.5%）

2. **涨跌停/不可成交建模**：
   - 涨停封板→买单无法成交（除非后续开板）
   - 跌停封板→卖单无法成交
   - 封板强度建模：封单量/流通盘、"炸板"概率

3. **T+1 / 停牌处理**：
   - 买入的股票当天不能卖出
   - 停牌期间无法交易，到期后恢复
   - 盘中临时停牌（新股涨跌30%/60%停10分钟）需处理

4. **资金约束**：
   - 整手化：按板块规则将理想股数向下取整到可执行单位
   - 最小配置额过滤：不达标的持仓砍掉，资金重分配
   - 账户级T+1资金可用性

5. **防过拟合机制**：
   - Walk-Forward滚动验证（非单次固定训练/测试划分）
   - Purged时序交叉验证
   - 回测无死角记录：每一笔信号的上下文快照，便于事后审计
   - **回测漂亮 ≠ 实盘赚钱**，过拟合是头号杀手

### 7.3 回测报告标准

- 净值曲线 + 基准对比
- 年化收益率、年化波动率
- 夏普比率、信息比率（IR）
- **最大回撤（MDD，实战最该盯）**
- 胜率、盈亏比、平均持仓天数
- 月度/年度收益热力图
- 换手率、总交易成本占比
- 因子IC序列、IC衰减曲线

## 十、仓位管理与资产配置

### 10.1 三层资产配置框架

#### 第一层：股票总仓位

```
股票总仓位 = 基准仓位 × 市场状态系数
```

**市场状态（Regime）判断**（非主观感觉，综合客观指标）：
- ① 趋势：指数与长期均线（200日线）关系、均线多空排列
- ② 波动率：已实现波动率分位、iVIX/历史波动率分位
- ③ 估值：全市场/指数PE-PB历史分位
- ④ 市场宽度：上涨家数占比、创新高家数、涨停温度

实现方式：简单打分模型或HMM/规则模型，划分"牛/熊/震荡 × 高波动/低波动"状态 → 映射总仓系数。

| 市场状态 | 总仓位参考 |
|---------|----------|
| 牛市 + 低估值 | 80%-90% |
| 震荡市 | 50%-70% |
| 熊市 + 高估值 | 30%-50% |
| 极端恐慌 | ≤30% |

**永远不满仓**：预留现金作为"相关性为零、波动为零"的有效降险工具。

#### 第二层：长期仓 vs 短期仓比例

核心-卫星框架：
- 长期仓（压舱石）：60%-80%
- 短期仓（增强）：20%-40%
- 新手短期仓 ≤20%

短期仓 = "亏得起的钱"——完全亏掉不影响生活和心态。

#### 第三层：池内每只票比例

推荐顺序（由简到繁）：
1. **等权**（最该先用的基线——实证常打败复杂方法）
2. **波动率倒数加权**（性价比最高，显著改善回撤）
3. **风险平价**（考虑相关性，风险贡献相等）
4. **按信号强度/置信度加权**（设单票上限≤20%-25%）
5. **均值-方差/凯利**（理论最优但对输入误差极敏感，须用半凯利或1/4凯利）

**凯利公式（股票连续收益版）**：
```
f* = μ / σ²
```
其中μ为期望超额收益，σ为收益波动率。实际使用半凯利：`f = 0.5 × f*`，或1/4凯利。

### 10.2 持股数量与资金量关系

**核心认知**：比例（权重）与总金额无关；但能持几只强烈依赖总金额。

| 约束 | 说明 |
|------|------|
| **分散化上限** | 20-30只（分布在不同行业）即消掉绝大部分可分散风险，与金额无关 |
| **可行性下限** | `只数 ≈ 股票总资金 / 单只最小合理配置额`；单只最小额 ≈ max(几手金额, 总资金×单票最小权重)，且让单笔佣金占比<0.1% |
| **精力上限** | 短期仓实际能管好2-5只 |
| **板块最小单位** | 主板100股、创业板100股、科创板200股起、北交所100股 |

**整手化/可行性层的系统实现**：
```
理想权重 → ×总资金=理想金额 → 按板块规则向下取整到可执行单位
  → 检查每只是否达最小配置额/手续费占比；不达标则砍掉、资金重分配
  → 迭代至剩下的票都满足约束
  → 输出：实际只数 + 整手持仓 + 真实权重
```

## 十一、退出机制

### 11.1 核心原则

> **退出规则在买入时（冷静时）定好，退出触发在当下（检验规则是否被触碰）。**

当下分析是为了检验预设逻辑是否仍成立，而非临时找理由。

### 11.2 长期仓退出

**盯"逻辑"，不盯"价格"。**

该卖：
- 买入逻辑被破坏（最重要！）
- 估值严重高估（超出历史2σ）
- 发现更好机会（机会成本）
- 基本面踩雷（无条件立即退出）
- 再平衡被动减仓

不该卖：
- 单纯因为跌了
- 短期情绪/噪声干扰
- "落袋为安"卖飞牛股

做法：不设机械止损价（会被正常波动洗出），设"逻辑检查清单"定期复核。

### 11.3 短期仓退出

**盯"价格和纪律"，机械执行。**

三个出口，买入前定好：
1. **止损位**（最重要）：技术位 / 固定比例 / ATR倍数止损；**只能往盈利方向移，永不下移或取消**；注意跌停封死无法成交→须早出
2. **止盈位 / 移动止盈**：固定目标价 或 trailing stop（从最高点回撤X%就卖）
3. **时间止损 / 逻辑止损**：催化剂兑现或证伪即走；N天不按预期走即退；T+1下尾盘/集合竞价处理避隔夜风险

### 11.4 系统实现

- **长期仓监控器**：跟踪基本面/估值变化，触发"逻辑复核"提醒（非自动卖出，人工确认）
- **短期仓监控器**：实时盯价，自动计算移动止盈/止损/时间止损，并发可执行信号
- **统一风控层**：熔断时短期仓优先无条件减，长期仓按逻辑审慎处理

## 十二、长短期系统解耦

### 12.1 架构原则

> **模型层彻底解耦，数据层共享，资金层硬隔离，组合层有限协同。**

三子系统通过时间维度形成层层聚焦的漏斗：

```
长期选股（月度，全市场~5000+只）
      │ 底池筛选 + 方向约束
      ▼
盘前推荐（日频，~30-80只精选）
      │ 关注清单 + 入场区间
      ▼
日内预测（分钟，~5-15只高频跟踪）
```

每一层缩小关注范围、提高时间精度、切换主导因子——但共享同一套数据基础设施和风控框架。

### 12.2 三子系统对比

| 维度 | 长期选股系统 | 盘前推荐系统 | 实时/日内系统 |
|------|------------|------------|-------------|
| 时域 | 月~年 | 盘前（当日，过期即失效） | now→收盘（分钟~小时） |
| 主驱动 | 基本面、估值、行业、护城河 | 隔夜信息 + 盘前公告 + 竞价信号 | 资金、情绪、盘口 |
| 数据 | 财报、宏观，低频 | 海外市场、公告、竞价、龙虎榜复盘 | tick/Level-2，流式 |
| 换手频率 | 月度调仓 | 每日生成、当日失效 | 盘中可能多次 |
| 建模 | 多因子横截面打分/排序 | 信号融合排序 + 事件驱动分类 | 分位数回归/分类，非平稳处理 |
| 评估 | 年化收益、回撤、IR、跑赢基准 | 开盘方向准确率、推荐命中率 | 方向准确率、日内夏普、校准度 |
| 噪声 | 相对低（月频平滑） | 中等（日频，隔夜信息消化） | 极高（分钟级随机游走） |
| 失败模式 | 价值陷阱、行业衰退 | 隔夜映射失效、竞价虚假信号 | 过拟合、交易成本吃掉收益 |

### 12.3 共享 vs 不共享

**该共享**：数据采集、清洗、复权、特征存储（部分）、风控引擎、监控、NLP模型（共用Qwen3实例，按需调用）

| 共享组件 | 长期系统使用 | 盘前系统使用 | 日内系统使用 |
|---------|-----------|-----------|-----------|
| 数据采集管线 | 日线/财报/宏观 | 公告/NLP/竞价/海外 | tick/L2/实时 |
| DolphinDB因子计算 | 月度离线计算 | 日频定时(8:00) | 实时流计算(≤5ms) |
| Redis特征缓存 | 月度更新 | 日频更新 | 秒级更新 |
| Qwen3 NLP模型 | — | 公告情绪/事件分类 | 实时新闻情绪 |
| LightGBM训练框架 | ✓ | ✓ | ✓ |
| 风控引擎 | ✓ | 提供总仓位建议 | ✓ |
| 监控告警 | ✓ | ✓ | ✓ |

**不该共享**：模型（各自独立的模型权重和超参）、预测时域、调仓节奏、评估指标

### 12.4 三个资金池

- **核心仓（长期）**：长期系统月度调仓，日内系统无权动它，盘前推荐仅影响其建仓/减仓时点
- **交易仓（短期）**：日内系统分钟级操作，严格止损，独立核算
- **盘前推荐不设独立资金池**——它是信息融合和筛选层，不直接产生交易指令；它的产出是"今日关注清单"，由日内系统在执行时决定是否交易

### 12.5 有限协同

- 长期系统定底池和方向 → 盘前推荐在此基础上每日精选 → 日内系统在精选池内定时点
- 长期评分作为盘前融合模型的基线输入特征（非硬约束：强隔夜信号可突破低长期评分）
- 盘前推荐的composite_score + expected_direction + suggested_entry_range 作为日内模型的先验特征
- 三系统共享情绪/资金面特征，统一风控约束（单票上限、行业集中度、回撤熔断）
- NLP模型实例共用：盘前推荐用于公告分析（日频批量），日内系统用于实时新闻（流式单条）——共享GPU资源，错峰使用

## 十三、策略组合与风险管理（风险最小化）

### 13.1 风险最小化定义

"风险最小" ≠ "波动最小"，而是在**需要的收益水平下把风险压到最低**（有效前沿）。

风险的多面性：
- 波动率（σ）
- **最大回撤（MDD，实战最该盯）**
- 尾部风险（VaR/CVaR）
- 流动性风险
- 相关性风险
- 估计误差风险（隐形最大风险）

### 13.2 八大发力点

1. **降相关是第一引擎**：
   - 跨行业/风格/市值配置
   - 让长短期收益来源不相关（天然对冲）
   - 警惕伪分散（计算组合平均相关系数，比只数更能反映真实分散）

2. **波动率加权/风险平价**：而非资金等权——避免少数高波动票贡献大部分风险

3. **直接优化回撤/尾部**：优化CVaR而非方差；组合级回撤熔断；波动率目标自动随波动调仓

4. **留现金**：相关性=0、波动=0的有效降险工具

5. **策略间再平衡和止损**：某策略连续回撤→按规则降其资金权重

6. **协方差估计用收缩法**：Ledoit-Wolf收缩估计，加约束/正则，保持结构简单

7. **对冲系统性风险（Beta）**：
   - 工具：股指期货（IF/IC/IM）、ETF期权/股指期权
   - 新手：先用最简单的"降仓位+留现金"替代复杂对冲
   - 成本：基差、贴水、权利金、保证金占用
   - 需开通对应权限（50万门槛），属于合规与权限范畴

8. **极端行情预案**：
   - "卖不出去"=必然会发生的场景，非例外
   - 优先减可成交的、流动性好的持仓
   - 无法离场→转用股指期货对冲
   - 预设最坏情形资金/保证金缓冲

### 13.3 因子层面的风险管理

1. **优先低风险因子**：低波动率（Low Vol异象）、质量（高ROE、低杠杆、稳定盈利）、低Beta
2. **因子多元且低相关**：单押一个因子意味着押注它一直有效，但因子会失效和轮动
3. **警惕陷阱**：
   - 价值陷阱→低估值叠加质量过滤
   - 数据泄露/前视偏差
   - 幸存者偏差（回测须含退市/ST完整历史）
   - 过拟合/数据挖掘（坚持经济学逻辑）
   - **因子发布后的衰减效应**：被公开发表的因子，实盘表现相较于论文中的回测结果通常衰减30%-50%
4. **A股特有因子**：
   - 小市值因子强但伴随高波动/踩雷风险
   - 流动性因子（避开卖不掉的票）
   - 政策题材驱动强，需结合资金/情绪面
5. **风险中性化**：对行业、市值做中性化，得到纯粹的因子收益

## 十六、附录

### 16.1 关键指标速查

| 指标 | 公式/说明 |
|------|---------|
| 夏普比率 | (年化收益 - 无风险利率) / 年化波动率 |
| 信息比率 (IR) | 年化超额收益 / 年化跟踪误差 |
| Rank IC | 因子值与下期收益的Spearman/Pearson相关系数 |
| ICIR | Rank IC均值 / Rank IC标准差 |
| 最大回撤 (MDD) | (峰值 - 谷值) / 峰值 |
| 凯利f* (连续) | μ / σ²（用半凯利或1/4凯利） |
| Calmar | 年化收益 / 最大回撤 |

### 16.2 每日收盘后检查清单

1. 数据完整性：行情/财务/资金流数据全部到齐
2. 模型预测值更新：无异常跳变
3. 信号生成：无冲突信号
4. 持仓风险敞口：行业/因子暴露/总仓位均在限额内
5. 回撤监控：距离熔断线的距离
6. 合规检查：申报笔数/撤单率未接近阈值

### 16.3 版本管理建议

- 因子/模型的每次迭代保留完整快照（代码 + 参数 + 数据时间戳）
- 回测结果可复现：固定随机种子 + 数据版本锁定
- 模型上线走审批流程：回测报告 → 模拟交易N天 → 小资金 → 逐步放量
