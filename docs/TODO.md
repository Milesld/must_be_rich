## 二、待实现（按优先级）

### ★★★ 1. 止损/止盈加入月度策略框架

**问题**：当前只有调仓日卖出（掉出 top-N）和紧急减仓（regime < 0.40）。日常没有止损保护。

**方案**：在 `on_bar()` 的非调仓日逻辑中加简单的止损/移动止盈：

```python
# 止损：任何持仓跌破成本价 -8% → 当日卖出
# 移动止盈：从最高点回落 >10% → 卖出
```

改动约 10-15 行代码，回测中可直接验证效果。

**可行性**：高。不改变选股逻辑，只加一条卖出规则。

---

### ★★★ 2. 时间衰减权重持续调优

**问题**：当前 halflife 是手动选的（半导体 1.0、机器人 1.5、苹果链 2.0、AI应用 2.0），没有系统化验证。

**方案**：
- 对每个池子分别跑 halflife ∈ {0.25, 0.5, 1.0, 1.5, 2.0, None} 的 optimizer
- 比较不同 halflife 下最优因子组合在验证窗口的外推夏普
- 选择外推夏普最高的 halflife 作为正式配置

**可行性**：高。6 个 halflife × 4 个池子 = 24 次 optimizer 运行，可在多核机器上并行。

---

### ★★ 3. AI 应用池重组

**问题**：当前 `strategy_ai_app.yaml` 的 21 只股票大部分是软件/信创/IT 服务，真正做 AI 大模型的只有科大讯飞、昆仑万维。池内股票相关性低，optimizer 夏普 1.33，是该池最弱的表现。

**方案**：将 AI 应用池改为 **AI 基础设施池**（算力租赁/数据中心/云计算），或拆分并入半导体池（光模块、算力服务器本就与芯片强相关）。

**可行性**：中。需要重新审视股票池、可能增加新股票代码、重跑 optimizer。

---

### ★★ 4. 信号加权（不等权买入）

**问题**：当前等权分配，评分 0.95 和 0.85 的股票买一样多，没有利用评分差异。

**方案**：`core/portfolio/optimizer.py` 已有 `signal_weighted()` 实现。改动 YAML 一行即可测试：

```yaml
strategy:
  optimizer: signal_weighted  # 从 equal_weight 改为 signal_weighted
```

加上集中度惩罚（单票不超过 25%）和分散度奖励。

**可行性**：高。已有代码，改配置即可测试。但对 top-2/top-3 场景收益有限——三只股票之间权重差 5% 的影响远小于"哪三只入选"本身。

---

### ★★ 5. 多策略并行自动调度

**问题**：当前跑 optimizer 是手动触发、串行等待。

**方案**：
```
核心1: 半导体池 optimizer (每周自动跑)
核心2: 机器人池 optimizer
核心3: 苹果链 optimizer
核心4: AI应用 optimizer

结果持久化到 CSV → 比较各策略夏普变化趋势
→ 某策略夏普连续 3 周下降 → 自动标记"策略退化" → 提醒人工审视
```

**可行性**：中。需要 (1) cron 定时任务 (2) 结果持久化 (3) 趋势报警。代码层面改动不大，主要是运维搭建。

---

### ★ 6. Walk-Forward 验证自动化

**问题**：`core/backtest/walk_forward.py` 代码已存在但未接入 optimizer。当前只用 2026H1 做了一层外推，样本太小（5-6次调仓）。

**方案**：对每个池子自动跑 4-6 期 Walk-Forward：
```
训练: 2023-01~2024-12 → 外推: 2025-Q1
训练: 2023-04~2025-03 → 外推: 2025-Q2
...
如果多期外推夏普都稳 → 因子有效
如果只有某几期好 → 过拟合
```

**可行性**：中。等实盘积累 6+ 个月调仓记录后更有意义。

---

### ★ 7. 子窗口夏普诊断

**问题**：optimizer 只输出一个 3 年总夏普，掩盖了"好坏年份"的差异。

**方案**：在 optimizer 结果报告中增加：
```
2023 夏普 | 2024 夏普 | 2025 夏普
  1.8    |   1.6    |   1.4    ← 稳健
  3.5    |   0.8    |   0.3    ← 红旗，2023 年爆炸后衰竭
```

改动约 30 行，在 `print_report()` 中加一段。

**可行性**：高。纯报告层改动，不影响优化逻辑。

---

### ★ 8. 接入实盘系统（最后一步）

**前提条件（未满足）**：
- 策略在验证窗口夏普 > 1.0 持续 3 个月以上
- 你对每个策略的选股逻辑有直觉认同（"为什么选这只"）
- 手动盯盘至少 1-2 个月，确认信号稳定

**当前阶段**：所有实盘操作应手动执行。自动化下单是最不应该提前做的事。

## 三、暂不考虑（近期不做）

| 方向 | 原因 |
|------|------|
| 短线（日内/周频） | 月度策略都还没验证够，跳到高频是找死。等月线跑 6-12 个月实盘再说 |
| 独立的卖出策略（每日判断两次） | 频率过高，噪音淹没信号。月度框架内加止损即可 |
| 接入 QMT 实盘下单 | 需要 50 万门槛 + 合规报告 + 券商对接。先手工验证 |
| 训练模型做权重拟合 | 过度设计。top-2/top-3 场景下等权 vs 信号加权差距微乎其微 |
