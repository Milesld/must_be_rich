**结构原则**：
- `core/` 是纯 Python 库，不启动进程，被各 service 依赖
- `services/` 是独立可部署单元，通过 gRPC/消息队列通信
- `cpp/` 编译为共享库（.so/.dylib），通过 pybind11 被 Python 调用
- `configs/` 是唯一配置来源，各 service 启动时读取，风控阈值等关键配置支持热加载

## 二、数据库表设计

### 2.1 设计原则

1. **行情数据走 ClickHouse/DolphinDB**（列存、高压缩、时序查询快），**业务数据走 MySQL**（ACID、事务、JOIN）
2. 每一张表都有 `created_at` 和 `updated_at`，数据只增不改（append-only），修正通过新版本行实现
3. 所有金额字段用 `Decimal(18,4)`，不丢精度
4. 股票代码统一为 `code` 字段，格式如 `'600519'`（6位数字字符串，无前缀）

### 2.2 行情数据表（ClickHouse / DolphinDB）

#### market_daily — 日K线

```sql
CREATE TABLE market_daily (
    trade_date  Date,
    code        String,            -- 如 '600519'
    name        String,            -- 如 '贵州茅台'（冗余，减少JOIN）
    open        Float64,
    high        Float64,
    low         Float64,
    close       Float64,
    pre_close   Float64,
    volume      Float64,           -- 成交量（股）
    amount      Float64,           -- 成交额（元）
    adj_factor  Float64,           -- 前复权因子
    turnover    Float64,           -- 换手率（%）
    is_st       UInt8,             -- 是否ST
    is_suspended UInt8,            -- 是否停牌
    status      LowCardinality(String)  -- 交易状态：正常/停牌/退市
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(trade_date)
ORDER BY (code, trade_date);
```

#### market_minute — 分钟K线

```sql
CREATE TABLE market_minute (
    trade_date  Date,
    time        DateTime,          -- 精确到分钟
    code        String,
    open        Float64,
    high        Float64,
    low         Float64,
    close       Float64,
    volume      Float64,
    amount      Float64
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(trade_date)
ORDER BY (code, time);
```

#### market_tick — L2逐笔（机构阶段使用）

```sql
CREATE TABLE market_tick (
    time        DateTime64(3),     -- 毫秒精度
    code        String,
    price       Float64,
    volume      Float64,
    amount      Float64,
    direction   Enum8('买'=1, '卖'=2, '中性'=3),
    bid_ask     Enum8('买盘'=1, '卖盘'=2),
    trade_type  String             -- 成交类型
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(time)
ORDER BY (code, time);
```

#### auction_snapshot — 集合竞价快照（盘前推荐用）

```sql
CREATE TABLE auction_snapshot (
    trade_date  Date,
    code        String,
    time        DateTime,          -- 9:15-9:25之间的快照时间点
    virtual_open Float64,          -- 虚拟开盘价
    matched_volume Float64,        -- 已匹配量
    unmatched_buy Float64,         -- 未匹配买单量
    unmatched_sell Float64,        -- 未匹配卖单量
    buy_orders_count UInt32,       -- 买单笔数
    sell_orders_count UInt32       -- 卖单笔数
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(trade_date)
ORDER BY (code, time);
```

### 2.3 基本面数据表（ClickHouse / DolphinDB）

#### financial_statements — 财务报表

```sql
CREATE TABLE financial_statements (
    code            String,
    report_date     Date,          -- 报告期截止日（如 2025-12-31）
    announce_date   Date,          -- ★实际披露日（防前视偏差的关键字段）
    statement_type  Enum8('年报'=1,'半年报'=2,'一季报'=3,'三季报'=4),
    -- 利润表
    revenue             Decimal(18,4),
    revenue_yoy         Float64,   -- 营收同比增速
    net_profit          Decimal(18,4),
    net_profit_yoy      Float64,
    gross_margin        Float64,
    net_margin          Float64,
    -- 资产负债表
    total_assets        Decimal(18,4),
    total_liabilities   Decimal(18,4),
    total_equity        Decimal(18,4),
    debt_ratio          Float64,
    current_ratio       Float64,
    quick_ratio         Float64,
    -- 现金流量表
    operating_cf        Decimal(18,4),
    free_cf             Decimal(18,4),
    cf_ratio            Float64,   -- 经营现金流/净利润
    -- 每股指标
    eps                 Float64,
    bps                 Float64,
    -- 盈利质量
    roe                 Float64,
    roa                 Float64,
    roic                Float64,
    -- 数据元信息
    data_source         String,    -- 数据来源
    version             String     -- 数据版本
) ENGINE = ReplacingMergeTree(version)
PARTITION BY toYYYYMM(report_date)
ORDER BY (code, report_date, statement_type);
```

### 2.4 因子/特征数据（DolphinDB + Redis）

#### DolphinDB: factor_values — 因子历史值

```sql
CREATE TABLE factor_values (
    factor_name     String,
    code            String,
    calc_date       Date,          -- 计算日期
    value           Float64,
    version         String         -- ★因子版本号（回测可复现的前提）
) PARTITION BY toYYYYMM(calc_date)
ORDER BY (factor_name, code, calc_date);
```

#### Redis: 实时特征缓存

```
Key模式：  feat:{factor_name}:{code}
Value：   {value, updated_at_timestamp}
TTL：     24小时（日频因子）/ 5分钟（实时因子）
```

### 2.5 业务数据表（MySQL，ACID）

#### account — 账户

```sql
CREATE TABLE account (
    id              INT AUTO_INCREMENT PRIMARY KEY,
    name            VARCHAR(64) NOT NULL,       -- 账户名称
    type            ENUM('core','trading') NOT NULL,  -- 核心仓/交易仓
    initial_capital DECIMAL(18,4) NOT NULL,
    current_cash    DECIMAL(18,4) NOT NULL,
    frozen_cash     DECIMAL(18,4) DEFAULT 0,    -- 冻结资金（挂单中）
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

#### position — 持仓

```sql
CREATE TABLE position (
    id              INT AUTO_INCREMENT PRIMARY KEY,
    account_id      INT NOT NULL,
    code            VARCHAR(6) NOT NULL,
    shares          INT NOT NULL,               -- 持仓股数（整数，已整手化）
    avg_cost        DECIMAL(10,4) NOT NULL,     -- 平均成本价
    current_price   DECIMAL(10,4),              -- 最新市价（日终更新）
    unrealized_pnl  DECIMAL(18,4),              -- 未实现盈亏
    realized_pnl    DECIMAL(18,4) DEFAULT 0,    -- 已实现盈亏
    open_date       DATE NOT NULL,              -- 建仓日期
    FOREIGN KEY (account_id) REFERENCES account(id),
    UNIQUE KEY uk_account_code (account_id, code)
);
```

#### signal_log — 信号日志（★合规审计核心★）

```sql
CREATE TABLE signal_log (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    generated_at    DATETIME(3) NOT NULL,        -- 信号生成时间（毫秒精度）
    code            VARCHAR(6) NOT NULL,
    signal_type     VARCHAR(32) NOT NULL,        -- buy/sell/hold/alert
    direction       ENUM('long','short','flat') NOT NULL,
    strength        DECIMAL(5,4),                -- 信号强度 0.0~1.0
    confidence      DECIMAL(5,4),                -- 置信度 0.0~1.0
    model_name      VARCHAR(64) NOT NULL,        -- 产生该信号的模型
    model_version   VARCHAR(32) NOT NULL,        -- 模型版本号
    feature_snapshot JSON NOT NULL,              -- ★当时的特征值快照（合规溯源）
    expiry_at       DATETIME(3),                 -- 信号过期时间
    status          ENUM('pending','executed','expired','rejected_by_risk','cancelled'),
    created_at      DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
    INDEX idx_code_time (code, generated_at),
    INDEX idx_status (status)
);
```

#### order_log — 订单日志

```sql
CREATE TABLE order_log (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    signal_id       BIGINT,                      -- 关联信号
    account_id      INT NOT NULL,
    code            VARCHAR(6) NOT NULL,
    side            ENUM('buy','sell') NOT NULL,
    price_type      ENUM('limit','market') NOT NULL,
    order_price     DECIMAL(10,4),
    order_shares    INT NOT NULL,
    submitted_at    DATETIME(3),
    filled_shares   INT DEFAULT 0,
    filled_avg_price DECIMAL(10,4),
    commission      DECIMAL(10,4) DEFAULT 0,     -- 佣金
    stamp_duty      DECIMAL(10,4) DEFAULT 0,     -- 印花税（仅卖方）
    transfer_fee    DECIMAL(10,4) DEFAULT 0,     -- 过户费
    status          ENUM('pending','partial_filled','filled','cancelled','rejected'),
    reject_reason   VARCHAR(256),
    created_at      DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
    FOREIGN KEY (signal_id) REFERENCES signal_log(id),
    INDEX idx_code_time (code, submitted_at)
);
```

## 三、组件间 API 契约

### 3.1 同步接口（gRPC）

| 调用方 | 被调用方 | 方法 | 请求 | 响应 | 延迟要求 |
|--------|---------|------|------|------|---------|
| 策略引擎 | 风控引擎(C++) | `CheckOrder` | `{code, side, price, shares, account_id}` | `{approved: bool, reject_reason: string}` | <10ms |
| 策略引擎 | 特征服务 | `GetFeatures` | `{codes: [], factor_names: []}` | `{features: {code: {factor: value}}}` | <50ms |
| 盘前服务 | NLP服务 | `AnalyzeSentiment` | `{text: string, source: string}` | `{sentiment: enum, confidence: float, event_type: string}` | <200ms |
| 盘前服务 | NLP服务 | `BatchAnalyze` | `{texts: [{id, text, source}]}` | `{results: [{id, sentiment, confidence, event_type}]}` | <30s(批量) |
| 订单管理器 | QMT/券商API | `SubmitOrder` | `{code, side, price_type, price, shares}` | `{order_id, status, message}` | <100ms |
| 订单管理器 | QMT/券商API | `CancelOrder` | `{order_id}` | `{success: bool}` | <100ms |
| 监控服务 | 各服务 | `HealthCheck` | `{}` | `{status, uptime, last_error}` | — |

### 3.2 异步事件（Redpanda Topics）

| Topic | 生产者 | 消费者 | 消息体（关键字段） | 保留策略 |
|-------|--------|--------|-------------------|---------|
| `market.tick` | data_collector | feature_server, risk_engine | `{code, price, volume, time, bid_ask}` | 24h |

### 3.3 信号统一格式（Pydantic Schema）

```python
from pydantic import BaseModel
from datetime import datetime
from enum import Enum

class Direction(str, Enum):
    LONG = "long"
    SHORT = "short"
    FLAT = "flat"

class SignalType(str, Enum):
    BUY = "buy"
    SELL = "sell"
    ALERT = "alert"

class Signal(BaseModel):
    signal_id: str           # 全局唯一ID: {service}.{uuid}
    generated_at: datetime   # 生成时间（毫秒精度）
    code: str                # 股票代码 '600519'
    signal_type: SignalType
    direction: Direction
    strength: float          # 0.0~1.0
    confidence: float        # 0.0~1.0
    model_name: str          # 产生该信号的模型名
    model_version: str       # 模型版本号
    entry_range: tuple[float, float] | None  # 建议入场区间(盘前推荐使用)
    expiry_at: datetime      # 信号有效期截止时间
    metadata: dict           # 扩展字段

class SignalAck(BaseModel):
    """信号接收确认"""
    signal_id: str
    status: str              # accepted / rejected / duplicate
    reason: str | None       # 拒绝原因
```

### 6.2 OMS 核心约束

1. **幂等性**：同一 `signal_id` 在任何情况下只产生一笔订单（数据库 UNIQUE 约束 + 应用层检查）
2. **部分成交处理**：剩余未成交部分设有效期（默认30秒），过期后自动撤单
3. **不可重复下单**：网络超时后最多重试1次，且重试前先查订单状态
4. **OMS 与风控同步阻塞调用**：风控返回拒绝则订单绝不发出
5. **所有订单操作记录 audit log**：不可删除、不可修改

### 7.1 测试金字塔

```
      └──────────┘
```

### 7.2 量化特有的测试场景

| 测试类型 | 验证目标 | 测试方法举例 |
|---------|---------|------------|
| **前视偏差检测** | 任何时间点只能使用该时刻之前已知的信息 | 给定2020-01-15，遍历所有因子的依赖数据，确认其 `announce_date`/时间戳 ≤ 2020-01-15 |
| **幸存者偏差检测** | 回测中已退市股票被完整保留 | 构造包含已知退市股的测试数据集，验证模型能选中它们，且回测结果中它们的交易记录存在 |
| **数值稳定性** | 极端行情下因子不爆炸、不产生 NaN/INF | 注入极端价格数据（一字跌停连续N天、价格跳空100%），确认所有因子输出有限值 |
| **回测可复现性** | 同样参数两次跑回测，结果逐笔一致 | 固定 seed + 锁定数据版本 + 锁定因子版本 → 连续跑2次 → 比较净值曲线与每笔成交的 checksum |
| **成本边界** | 小资金交易的佣金最低5元规则生效 | 构造1000/5000/10000元的买单，验证佣金分别为5/5/1.5元（万1.5费率下10000元≈1.5元但实收5元） |
| **涨跌停封板** | 封板后买卖单无法成交 | 回测中某日涨停封板，次日挂买单→应被拒绝成交或进入无法成交队列 |
| **T+1约束** | 当日买入的股票当日不能卖出 | T日买入→T日立即尝试卖出→应被拒绝 |
| **整手化精度** | 小资金下整手化迭代收敛 | 5万元账户→计算理想权重→整手化→验证输出每只持仓股数符合板块规则且总金额≤可用资金 |

## 十、开发中需要注意的关键事项（按坑深排序）

### 坑 #1：前视偏差

最隐蔽、最致命的错误。回测漂亮，实盘归零。

两个最高发错误：
- 2月10日的回测用到了"2月15日才披露"的财报数据——因为用了 `report_date <= '2020-02-10'` 而不是 `announce_date <= '2020-02-10'`
- 用"今天还活着的成分股列表"做历史筛选，但2019年时那些已退市的股票也是存在的

**防范**：
- 在 `core/features/` 中实现 `TimeTravelChecker`，每个特征计算前校验时间戳
- 财务数据管线强制使用 `announce_date` 作为可用时间点
- 回测数据库必须保留已退市股票的完整历史

### 坑 #2：回测和实盘的特征计算不一致

回测时 DolphinDB 批量算的因子，实盘时用 Python 重写了一遍——浮点精度、NA 处理方式、参数默认值的微小差异导致线上线下特征不同。

**防范**：
- "一个因子只写一次代码"——选择 Python 作为唯一的因子计算实现语言
- DolphinDB 的因子计算通过 Python UDF 调用同一份代码，而非在 DolphinDB 脚本中重复实现
- 定期做线上 vs 离线特征值的一致性校验（同交易日、同股票、同因子 → 差异应<1e-8）

### 坑 #3：涨跌停下的成交假设

回测中假设"涨停价挂买单能成交"是常见错误——涨停封板后，即使挂在涨停价也未必能买到（需有人卖出，且前方排队优先）。

**防范**：
- 回测引擎中区分"触板"（达到涨停价但未封死）和"封板"（大量买单排队，几乎无卖盘）
- "封板"判断依据：封单量/流通盘比例 + 是否开板
- 封板状态下买单进入"不可成交队列"，开板后才可能成交

### 坑 #4：小资金下的整手化偏差

5万元账户，茅台理想权重3.7%→1850元，一手16.8万→根本买不起。简单向下取整会砍掉所有高价股，组合严重偏离理想配置。

**防范**：
- 整手化是迭代收敛过程，不是一次性向下取整：砍掉买不起的 → 重新分配资金 → 再次整手化 → 直到收敛
- 输出中明确记录"理想权重 vs 实际权重"的偏差，偏差>5%的标的做标记

### 坑 #5：模型上线后衰减

从"回测优秀"到"实盘平庸"的窗口通常3-6个月。因子拥挤、市场结构变化都是原因。

**防范**：
- 自动化衰减检测：Rolling Rank IC 连续N周低于阈值（如0.02）→ 触发重训练告警
- 不把重训练周期写死为"每月一次"——用数据驱动触发
- 保持模型集合的多样性（GBDT + 线性 + 不同因子子集），单一模型失效时组合仍有韧性

### 坑 #6：NLP模型GPU资源争抢

盘前推荐（8:00-8:30 批量处理公告）和日内系统（9:30-15:00 实时处理新闻）共享同一个GPU——盘前任务拖到9:30后，会卡住日内实时推理。

**防范**：
- 盘前批量NLP任务的**硬截止时间为08:45**，超过直接丢弃剩余任务
- GPU调度层面设置抢占式优先级：日内实时推理 > 盘前批量
- 如预算允许，盘前和日内各自独立GPU实例

### 坑 #7：数据源中断的连锁反应

Tushare/AkShare 某天接口挂了——如果没有备用源，整个盘前推荐和长期系统当天就废了。

**防范**：
- 每个关键数据源配置主备双通道，采集时并行尝试
- 任一源成功即入库，记录成功来源
- 主源连续失败N次 → 自动切换为备用源作为默认
- 所有源均失败 → 降级运行（使用前一日缓存数据 + 大幅标记置信度下调）

### 坑 #8：模拟盘→实盘的心理关

模拟盘赚钱的策略，实盘可能亏钱。原因不只是延迟/流动性差异，更关键的是亏损带来的心理压力会让人手动干预策略。

**防范**：
- 实盘只用总资金的5%起步，跑2-4周验证真实表现（交易成本+滑点+心理压力）
- 运行期间坚持不手动干预——让数据说话而非情绪
- 如果无法做到不干预，先做"半自动"模式：系统生成信号，每天人工确认一次，不逐笔干预
